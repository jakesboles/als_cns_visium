# als_cns_visium

Working notes for Claude Code sessions on this repo. This file is a running memory dump, not a tutorial — it exists so a fresh session doesn't have to re-derive context that's already been hard-won. Update it as the project evolves; don't let it go stale.

## What this project is

Visium spatial transcriptomics across multiple CNS/muscle tissue compartments from an ALS cohort (motor cortex, cervical spinal cord, skeletal muscle), comparing C9orf72-ALS, sporadic ALS (sALS), and Control donors. This repo is approaching a "final" version that will accompany a manuscript and will eventually be merged with sibling repos covering scRNAseq (`jakesboles/als_cns_scrnaseq`) and HMIF analyses from the same project.

The current scientific goal in flight: import Halo-annotated anatomical regions (gray matter, white matter, meninges, nerve bundles) and pathology features (pTDP-43, pGA aggregates) from a registered high-resolution image, use them to classify each Visium spot, integrate spots across samples with Harmony, and run pseudobulk DESeq2 within each anatomical compartment.

## Rules of engagement

- **Never edit files directly without being asked.** Every change goes through a PR on the session's designated feature branch — this was set explicitly at the start of the project and hasn't been rescinded.
- **If a PR's branch has already been merged, restart it from the current `main` before adding new commits** (`git fetch origin main && git checkout -B <branch> origin/main`, force-with-lease push). Never stack new work on top of already-merged history on the same branch name.
- **Match this repo's existing coding style**, not a generic one: R scripts use `tidyverse`/`Seurat`/plain `message()` calls (no `message2()` banner helper — that's a stylistic convention from the scRNAseq sibling repo, not this one), 2-space indentation in both R and Python, trailing-slash string concatenation for paths (`paste0(dir, "file")` / `f"{dir}file"`) rather than `file.path()`/`os.path.join()`.
- **Match the existing `data_dir`/`results_dir` split**: generated data objects (RDS, BPCells dirs) go under `data/<script_name>/`; plots and CSV summaries go under `results/<script_name>/`. Both are gitignored (see `.gitignore`: `results/*`, `plots/*`, `data/*`, `envs/*`, `logs/*`, `__pycache__/`). Every script's own subfolder is named after the script (e.g. `data/04_spot_annotation/`, `results/05_integration/`).
- **Every script that runs on the cluster gets a matching `jobs/<script_name>.sh` SLURM wrapper**, `#SBATCH --account b1169 --partition b1169`, log path `/gpfs/projects/b1169/boles/als_cns_visium/logs/%x_%j.log`. Python scripts activate the `Stardist` conda env (`source activate "/projects/b1169/thomas/StardistEnv/env/Stardist"`); R scripts `module load R/4.4.0` + `module load hdf5/1.14.1-2-gcc-12.3.0` (mirrors the scRNAseq repo's `jobs/deseq2.sh`).
- **This session has no cluster access and no real data** — no Space Ranger output, no Halo annotations, no R or Python interpreter with the actual packages installed. Every fix is a careful read/reasoning-based edit, never an executed/tested one. Always say so explicitly rather than implying something was verified by running it.
- **When something is a genuine judgment call** (a design ambiguity, a choice only the user can make, a bug fix that changes semantics), ask rather than guessing — this user explicitly invites clarifying questions and has been very responsive to `AskUserQuestion`-style check-ins.
- **Don't assume a "bug" without checking the data-generating history.** More than once a change that looked like an obvious logic inversion turned out to be compensating for a real upstream data quirk (see "Known data quirks" below) — the user caught this after a merge and corrected it. When flagging something as a bug, be clear about confidence level and be ready to be wrong.
- **The `als_cns_scrnaseq` sibling repo is a structural template, not a style authority.** It's the right place to look for *how* to do something (BPCells save/load pattern, DESeq2 pseudobulk structure, IHW usage) but its exact naming/helpers (`message2()`, assay named `"RNA"`, `orig.ident` conventions) don't automatically transfer — this project's own scripts take precedence, and assay names in particular differ (`"Spatial"` here, `"RNA"` there). Copy-pasting from it without adapting names has caused at least one real bug (`obj[["RNA"]]` referenced in a script that only ever has a `"Spatial"` assay).

## Pipeline, stage by stage

### `01_obj_creation.R`
Loads each sample's Space Ranger output via `Load10X_Spatial()`, adds spatial metadata from `tissue_positions.csv`, renames cells with `RenameCells(add.cell.id = sample_id)`, splits into `cns_obj`/`muscle_obj` by a hardcoded muscle-sample list, merges each group, and writes BPCells on-disk matrices. Excludes a fixed cohort-exclusion list (`137-1, 137-2, AN16-1, AN68-1, AN68-2, AN69-7, AN69-8`).

**BPCells pattern** (mirrors `als_cns_scrnaseq`'s `01_obj_creation.R`): write each sample's counts to its own on-disk dir immediately after loading (`data/01_obj_creation/bpcells_persample/<sample>/`) so the merge never holds every sample's sparse matrix in memory at once; after `Merge_Seurat_List()` + `JoinLayers()`, write one consolidated matrix per group (`bpcells_cns/`, `bpcells_muscle/`); save `@meta.data` and `@images` as separate RDS files (`cns_metadata.rds`/`muscle_metadata.rds`, `cns_images.rds`/`muscle_images.rds`) since BPCells only covers the counts matrix. Every script that follows this pattern documents the reconstruction recipe in a trailing comment:
```r
counts <- open_matrix_dir(paste0(data_dir, "bpcells_cns"))
meta <- readRDS(paste0(data_dir, "cns_metadata.rds"))
images <- readRDS(paste0(data_dir, "cns_images.rds"))
obj <- CreateSeuratObject(counts = counts, meta.data = meta, assay = "Spatial")
obj@images <- images
```

**setwd() inconsistency**: `01_obj_creation.R` and `02_qc.R` `setwd("/projects/b1169/boles/als_motor_circuit_visium/")`, while `03a`/`03b`/`03c`/`04`/`05`/`deseq2_by_compartment.R` all `setwd("/projects/b1169/boles/als_cns_visium")` — a different directory name. Flagged to the user once; not yet confirmed whether this is a real problem (two genuinely different directories, meaning `01`/`02` may be reading/writing somewhere the rest of the pipeline never looks) or a harmless leftover (e.g. a symlink). Worth re-checking if a downstream script ever can't find `01`/`02`'s output.

### `02_qc.R`
Reads `01`'s CNS BPCells output, adds mito/ribo/complexity metrics, computes per-sample UMI/feature/mito thresholds (median ± MAD, with a floor), flags spots for discard (including edge-of-capture-area spots via `array_row`/`array_col` min/max), and writes the QC-filtered object back out the same way (`data/02_qc/bpcells_cns`, `cns_metadata.rds`, `cns_images.rds`) — a fresh on-disk matrix, since discarding spots changes the counts matrix (unlike a step that only adds metadata columns, which just reuses the existing on-disk matrix per the scRNAseq repo's convention).

### `03a_make_spot_gdfs.py` (job: `03a_make_spot_gdfs.sh`)
Builds a `geopandas` GeoDataFrame of Visium spot geometries (55px-radius circles at `pxl_col/row_in_fullres`) for each CNS sample, filtered to `in_tissue == 1`. Confirmed with the user: `images_for_alignment/*.tiff` (the separately-registered image Halo actually annotated) is pixel-identical to what Space Ranger's fullres coordinates reference — the only processing difference is bit depth (16→8) and channel flattening to pseudocolor, neither of which affects pixel geometry, so no coordinate scaling is needed. Saves each sample's spot GDF as **GeoParquet** (`data/03a_make_spot_gdfs/<sample>/gdf_spots/gdf.parquet`), with `barcode` kept as a **plain column** (never the index) so it round-trips unambiguously — GeoParquet was chosen over Shapefile specifically for portability (single file, no field-name truncation, reliable dtype/CRS round-trip) since these GDFs are meant to be reusable beyond this one project. Also writes one combined, downsampled multi-panel PNG (`results/03a_make_spot_gdfs/ST_spots.png`) instead of one file per sample.

Sample list is a hardcoded 47-sample list (CNS only: `mcx`/`sc` tissue, no muscle) — not derived dynamically from `01`'s exclusion logic, so if the cohort exclusion list ever changes, this list needs manual updating too.

### `03b_make_halo_gdfs.py` (job: `03b_make_halo_gdfs.sh`) — anatomical regions
Loops over every category subfolder under `data/halo_annotations/anatomy/` (`mcx_meninges`, `mcx_wm`, `sc_gm`, `sc_meninges`, `sc_nerve_bundles`), each holding one geoJSON per annotated sample (filenames like `<sample>_Scan1.unmixed.geojson`, though scan number isn't always `1` — sample id is recovered by splitting on `_Scan[0-9]+`, not a fixed suffix). For each sample+category: loads the geoJSON, keeps only `geometry` (drops Halo's bookkeeping columns unconditionally rather than by name, since schema can differ across annotation types), converts LineStrings to polygons, unions them, and classifies a spot as **"in" the region if >50% of its area is covered** by the (dissolved) region polygon(s) — not full containment, which would systematically exclude every spot straddling a region boundary. Writes GeoParquet ROI GDFs, one combined results CSV per sample (`results/in_roi.csv`, one boolean `in_<category>` column per category that sample was actually annotated for — a category never annotated for that sample is simply absent as a column, not `NaN`/`False`), and one combined per-category PNG plot.

### `03c_make_halo_feature_gdfs.py` (job: `03c_make_halo_feature_gdfs.sh`) — pathology features
Structurally identical to `03b` but points at `data/halo_annotations/features/` (`mcx_pga`, `mcx_ptdp`; `sc_ptdp` annotation work is still in progress as of this writing) and classifies a spot as containing a feature via `geometry.intersects()` — **any overlap at all**, no area threshold — since a feature annotation (an aggregate, a cell) can sit anywhere within a spot rather than being a region the spot should be mostly inside of. This anatomy-vs-feature classification distinction (majority-area vs. any-overlap) was an explicit, deliberate design decision, not an oversight — don't "fix" one to match the other.

Both `03b` and `03c` read spot GDFs from `03a`'s output directory and cross-check sample ids against the same cohort-exclusion list used in `01_obj_creation.R`.

### `04_spot_annotation.R`
The metadata-merging hub: joins `02_qc.R`'s metadata with `master.xlsx` (sample→donor→tissue key) and `target_als_demographics_compiled.csv` (donor demographics), joins in `03b`'s and `03c`'s per-sample `in_roi.csv` outputs, derives a `region` column per spot (`GM`/`WM`/`Meninges`/`Nerve bundle`/`Remove`, tissue-specific `case_when` logic — mcx has no explicit unclassified category since unannotated mcx tissue defaults to `GM`; sc has an annotated `sc_gm` so an sc spot matching none of the four sc categories becomes `Remove`), derives `ptdp`/`pga` boolean columns from the `03c` features, makes per-sample QC/diagnostic plots, then builds a Seurat object, subsets to `region != "Remove"`, and saves the filtered object's own pieces directly:
- `data/04_spot_annotation/bpcells_data` (BPCells counts, already filtered)
- `data/04_spot_annotation/metadata.rds` (`@meta.data`, **real barcodes as rownames**, not a `barcode` column — `column_to_rownames()` happens right before `CreateSeuratObject()`)
- `data/04_spot_annotation/images.rds` (`@images`, already subset to match via Seurat's own `subset()`)

**This is the shape every downstream script should read from** — don't re-read `02_qc.R`'s unfiltered output and re-derive the filtering; `04` has already done it.

Downstream metadata columns of interest once `04` has run: `code` (Visium section id, e.g. `AN67-3`), `batch` (first token of `code` before a hyphen), `sample` (donor id, hyphens stripped), `tissue` (`mcx`/`sc`/`musc`, from `master.xlsx`), `group` (`Control`/`sALS`/`C9orf72`, derived: `C9orf72 mutation == "Y"` → `C9orf72`; else `Clinical Diagnosis == "Control"` → `Control`; else `sALS`), `age`, `sex`, `region`, `ptdp`, `pga`, plus the original QC-era columns (`nCount_Spatial`, `nFeature_Spatial`, `array_row`, `array_col`, `percent_mito`, etc.).

### `05_integration.R`
Reads `04`'s output directly (`data/04_spot_annotation/{bpcells_data,metadata.rds,images.rds}`), runs `NormalizeData`/`FindVariableFeatures`/`ScaleData`/`RunPCA`, splits the assay by a per-Visium-section batch variable, runs Harmony via `IntegrateLayers()`, rejoins layers, and runs UMAP on the Harmony reduction. Saves `data/05_integration/bpcells_data` (normalized data layer), `harmony.rds`, `harmony_umap.rds`, plus PCA/UMAP diagnostic plots under `results/05_integration/`.

**In flux as of this writing**: the batch variable used for `split()` was `orig.ident`, which is very likely a constant across the whole object (nothing in `01`/`02`/`04` ever sets `orig.ident` to something sample-specific — `Load10X_Spatial()` doesn't take a per-sample `project` arg here, and `RenameCells(add.cell.id=...)` only renames cells, not the `orig.ident` column) — meaning `split()` on it would silently produce a single layer and make the whole Harmony step a no-op with no error. The user confirmed the batch variable should be `code` instead, and is making that change themselves (both the `split()` call and, probably, the matching entry in the per-`group.by` `DimPlot_scCustom` loop — easy to fix one and miss the other).

### `deseq2_by_compartment.R` (job: `deseq2_by_compartment.sh`)
Pseudobulk DESeq2 across 4 fixed anatomical compartments (mcx GM, mcx WM, sc GM, sc WM), reading directly from `04`'s output. Modeled closely on `als_cns_scrnaseq/r_scripts/deseq2.R`'s per-cell-type structure, adapted to per-compartment: `AggregateExpression()` pseudobulks by **donor** (`sample`), not Visium section, so a donor with multiple sections of the same tissue still contributes one pseudobulk column; per-compartment abundance filtering (`min_spots_per_sample`/`min_samples_per_group`, both tunable) with a `sample_filtering.csv` written before the skip check; `design = ~ sex + age_scale + group` (age centered/scaled per compartment, `Control` as the reference level); `results()` with `filterFun = ihw, independentFiltering = T` for both contrasts (`sALS` vs `Control`, `C9orf72` vs `Control`), each followed by `lfcShrink(type = "apeglm")`; whole per-compartment pipeline wrapped in `tryCatch` so one compartment's failure doesn't kill the others. `dds.rds` files go under `data/deseq2_by_compartment/` (not alongside the `results/` CSVs like the scRNAseq script does) to match this repo's stricter `data/`-vs-`results/` split.

A separate follow-up script (not yet written) will do the same for the non-anatomical feature annotations (pTDP-43, pGA) once those annotations — especially `sc_ptdp` — are complete.

## Cohort / sample-naming details

- **Tissue codes**: `mcx` (motor cortex), `sc` (cervical spinal cord), `musc` (skeletal muscle, sometimes blank/`NA` in `master.xlsx` for a couple of rows).
- **Muscle samples** (excluded from the CNS object in `01`): `JSB147-7`, `JSB147-8`, `AN69-1` through `AN69-6`.
- **Cohort exclusion list** (excluded everywhere): `137-1`, `137-2`, `AN16-1`, `AN68-1`, `AN68-2`, `AN69-7`, `AN69-8`.
- **Sample id / "code" naming is inconsistent between `master.xlsx` and the actual Space Ranger directory names**: batches `137`, `146`, `147` are bare (`146-1`) in `master.xlsx`'s `code` column but need a `JSB` prefix (`JSB146-1`) to match the real sample id used everywhere else (Space Ranger dirs, Seurat cell name prefixes, `03a`'s sample list); batches `AN67`, `AN72`, `JSB163`, `JSB164`, `JSB171` already carry their real prefix in `master.xlsx`. `04_spot_annotation.R`'s `key` table normalizes this with `if_else(str_detect(code, "AN|JSB"), code, paste0("JSB", code))`.
- **Halo annotation categories observed** (under `data/halo_annotations/`, reorganized into `anatomy/` and `features/` subfolders): `anatomy/{mcx_meninges, mcx_wm, sc_gm, sc_meninges, sc_nerve_bundles}`, `features/{mcx_pga, mcx_ptdp}` (`sc_ptdp` in progress). Not every sample is annotated for every category in its tissue — coverage varies per category.

## Known data quirks / troubleshooting history

- **Cell barcode format has a leading underscore anomaly.** At some point a `"_"` got prepended to all cell barcodes (rownames) in the pipeline, so a cell name that would otherwise be `"<sample_id>_<10x_barcode>"` is actually `"_<sample_id>_<10x_barcode>"`. This means splitting rownames on `"_"` to recover the sample code needs the **second** field, not the first — `str_split_i(rownames(meta), "_", i = 1)` extracts an **empty string**, not the sample code. **This was the subject of repeated back-and-forth in this project's history**: it looks exactly like a classic off-by-one bug (and would be one, absent the leading underscore), so it's been "fixed" from `i = 2` to `i = 1` more than once based on how `RenameCells(add.cell.id=...)` normally names cells — each time, wrongly, because the leading-underscore quirk changes which index is actually correct. The user is the authority on which index is currently right in `04_spot_annotation.R`; don't re-"fix" this line without first checking `rownames(meta)`'s actual current format (e.g. `head(rownames(meta))`) rather than reasoning from `RenameCells()`'s documented behavior alone.
- **`region == "Remove"` vs `region != "Remove"`**: an earlier version of `04_spot_annotation.R` filtered `region == "Remove"` right before saving, keeping only the ambiguous/unclassified spots and discarding everything actually classified — backwards relative to the surrounding comment's intent. Fixed to `!=`. Now superseded by a proper `subset(obj, region != "Remove")` on the Seurat object itself.
- **`filter()` doesn't work on Seurat objects.** An intermediate version of `04` had `obj <- obj %>% filter(region != "Remove")` — `dplyr::filter()` has no method for Seurat's S4 objects. Must be `subset(obj, region != "Remove")`.
- **Assay name mismatches when porting patterns from `als_cns_scrnaseq`**: that repo's Seurat objects use an assay named `"RNA"`; this project's Visium objects use `"Spatial"`. Copy-pasting a `obj[["RNA"]]$data`-style reference without renaming the assay is an easy, silent-until-runtime mistake — check for this specifically whenever code is adapted from the scRNAseq repo.
- **BPCells `write_matrix_dir()` needs an explicitly-typed integer matrix.** `dgCMatrix`'s `@x` slot is always R type `"double"` regardless of the values it holds; call `convert_matrix_type(mat, type = "uint32_t")` before writing, every time (this is why every BPCells-writing step in the pipeline has that conversion line).
- **`AggregateExpression()` sanitizes `"_"` → `"-"` in `group.by` values internally**, even with a single `group.by` column — matters when matching `colnames(exp)` back against a metadata table by donor/sample id. Not actually a problem in this repo's `deseq2_by_compartment.R` since `sample` (donor id, from `target_als_demographics_compiled.csv` with hyphens already stripped) never contains an underscore in the first place — but worth remembering if a future script pseudobulks by a variable that might.
- **GeoParquet over Shapefile** for all Python-side spot/ROI GDFs — a deliberate choice for portability (single file, no field-name truncation, no index-round-trip ambiguity), not the original colleague-authored scripts' choice (they used `.shp`).
